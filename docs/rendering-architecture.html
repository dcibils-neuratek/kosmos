Rendering modes - what they stand on

Every mode is already in the tree as a step measured on the M700; what is new is making the choice a setting rather than a build. Preferences writes the mode and tells the window manager; the window manager does the pointer itself and asks the window server for the rest with one verb; the window server turns its flips and its blits on or off. The GPU's driver does not change.

S - a mode chosen

  1. S1 Preferences writes rendering and shows the bar: 15 seconds to keep it.
  2. S2 the window manager is told, as of a new look, and moves the pointer: the cursor plane, or composed into the frame.
  3. S3 it asks the window server, one small message: flips, the blitter's copy, the blitter composing.
  4. S4 the window server switches and composes the whole screen once, so the mode starts from a whole frame.
  5. S5 the driver keeps its second screen once made; going back to Framebuffer flips to the firmware's.

N - the numbers

  1. N1 once a second while the page is open: gpu.stats - flips, the blitter, memory.
  2. N2 and the window manager's own count of frames and the processor's time a frame, as frames reads it.
