Sandboxes

Small operating systems - Linux first - started for a task or kept as a service, each given only what is chosen for it: processors, memory, one or two folders of /Home, and the network only if asked. Diego, 11 October 2026: "to launch sandboxes to run small OSes like linux for specific tasks", "can firecracker launch long lasting processes. like a http server in linux?", "can you mockup how sandbox app and system would look like to launch new sandboxes and manage and monitor them?". The architecture is docs/virtualization.md; this is how it looks. Made-up sandboxes throughout.

Kosmos

The Sandboxes application: the sidebar's groups - All, Running, Stopped, Tasks - then the images there are to start from and what the machine has given. Each sandbox is a card: what it runs and for how long, a pill for its state (running, a task, stopped), its processors and memory as they are used now, and what it was given - its ports, its folders, its network. The one chosen is ringed; its buttons are the card's.

Kosmos

In Processes, each sandbox is one process, its monitor vmm, with its virtual processors among its threads and the guest's memory counted to it - so Monitor and Processes need nothing new to show what sandboxes cost.
