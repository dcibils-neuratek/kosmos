The Graph Kit - what it stands on

A program declares its work as tasks - scalar (Lua, in a worker's own state), work (C, from a kit) and parallel (a kernel, or its fallback on the processor) - and the edges between them. The kit runs the graph on one worker a core: a task runs, emits what follows it, and ends; nothing waits, nothing locks. Data lives in Compute Kit buffers every task and the GPU see; what travels with a task is 64 bytes. Stage 1 is the processor alone; stage 2 runs the parallel tasks on the GPU with the program unchanged.

T - a contact sheet, 48 photos, 4 workers

  1. T1 graph.app{...}: the declaration checked once, every rule with its line; four workers made, a state each.
  2. T2 g:emit("list", {folder}): one 64-byte record, one wake.
  3. T3 list.lua on worker 0 reads the folder and emits 48 decode records, 12 a ring.
  4. T4 each worker pops a record; its arguments - a path, a slot - come out of the arena.
  5. T5 gfx.decode_picture in C: the time of the whole program, on four cores; the pixels adopted as a buffer; place emitted, which scales into the sheet and adds one to done.
  6. T6 the 48th place brings the join to 48 and emits shade: four ranges over the fallback (stage 1), one run on the GPU (stage 2).
  7. T7 the window's tick reads g:events() and damages one thumbnail's rectangle; the pixels are already in the sheet it shows.

What a task may not do

Waitno sleep, receive or call; it ends and emits
Shareno table crosses a worker; no field has two writers
Reachno buffer it was not handed; the namespace only through the main state
