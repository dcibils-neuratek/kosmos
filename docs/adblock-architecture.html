Blocking in JetSki - what it stands on

WebKit already carries Safari's content blocker; Kosmos turns it on and feeds it. One new library converts the public filter lists into its rules, and JetSki and Mail share what it makes. A blocked request is decided inside the web process in microseconds and is never made.

R - a page's request

  1. R1 WebCore is about to ask for a script, a picture or a frame.
  2. R2 Its address runs through each list's bytecode, in memory: microseconds.
  3. R3 Blocked: no DNS lookup, no TLS handshake, no bytes, no script, no cookie.
  4. R4 Let through: a third party's cookie is not kept.
  5. R5 The rule's identifier reaches JetSki, which counts it on the shield.

U - a list updated

  1. U1 JetSki sees a list's Expires has passed, or Update now.
  2. U2 The list is fetched over HTTPS.
  3. U3 filters.lua converts it, off the window's path.
  4. U4 WebKit compiles it on a work queue; the old file serves until the new one is ready.
