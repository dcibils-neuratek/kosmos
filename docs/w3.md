# W3 - the POSIX layer, inside the process, for JetSki

*Designed 11 November 2026, the day the line it stands on moved (Diego:
"Amend the principle", `design.md` §17.3). W3d's door agreed the same day:
a Storage Kit in C (Diego chose it, as recommended).*

JetSki is WebKit on Kosmos (`docs/webkit.md`). WebKit, curl, ICU,
FreeType, SQLite and libxml2 are written against POSIX: pthreads, `mmap`,
descriptors, `open` and `read`, sockets and `poll`, `clock_gettime`. W2 gave
Nebula what those stand on - a futex, memory reserved and protected, a
thread suspended - and W3 is the layer that turns them into the names the
ports call.

**In short.** A library, `runtime/posix/`, linked by ported code only and
never included by Kosmos's own kits, servers and applications. Five parts,
built in this order; the first two are decided by what W2 built and the
rest by one question below.

---

## What it is not

The line (`design.md` §17.3): **no `fork`, no `exec`, no signals, no
`ioctl`, no path past the process's namespace, no descriptor that crosses
from one process to another, no authority the process was not handed.**
Where a port calls one of those, its Kosmos files say what to do instead -
a build step, never an edit to the vendored tree. `getpid` answers the
process's id; `getuid` answers 0, because there are no users to be.

## W3a - pthreads

*Built 11 November 2026* (`testing.md` 18.768): `runtime/posix/pthread.c`,
`pthread.h` and `sched.h`, held by `posixtest.elf` in `x86-loader` and
`arm-loader`. As built: the ring and rwlock checks wait with a deadline,
so a lost wake is a sentence rather than a hung suite; and the mutex
control bites on ARM only, since QEMU runs an x86 guest's processors one
at a time here.

On Kosmos threads (`SYS_THREAD_CREATE`) and the futex.

- `pthread_create`, `join`, `detach`, `self`, `equal`, `exit`; attributes
  for a stack size (refused above the 1 MB slot rather than ignored) and
  detached state;
- `pthread_mutex_*`, normal and recursive, on `kosmos_lock`'s three states;
  `trylock`, `timedlock`;
- `pthread_cond_*` - a sequence word and a futex, `timedwait` on
  `CLOCK_MONOTONIC` and `CLOCK_REALTIME`;
- `pthread_rwlock_*`, `pthread_once`, `pthread_key_*` (keys in the thread's
  own block, `USER_TBLOCK`, which W1's `thread_local` already uses);
- `pthread_getattr_np` and `pthread_attr_getstack`, which JavaScriptCore
  asks to find the stack it scans; `sched_yield`;
- `pthread_kill`, `pthread_sigmask` and the rest of signals: not present.
  JavaScriptCore's collector uses W2c's suspend instead, through its
  Kosmos file.

**Test**: a C program of checks in the gate (`posixtest.elf`, as
`cxxtest.elf` is): eight threads counting under a mutex; a condition
variable handing a token round a ring of threads a thousand times; a
`timedwait` that times out within a tick; `once` under eight threads at
once; keys with destructors run at exit; a recursive mutex. **Control**:
the mutex built with a plain load and store in place of its atomic
exchange must lose counts, and the condition variable without its
sequence word must lose a wake and time out.

## W3b - memory

*Built 11 November 2026* (`testing.md` 18.769): `runtime/posix/mman.c`.
As built, one correction to what is below: `madvise(MADV_DONTNEED)` is
not "released and committed again" - that would have had to guess each
page's access - but `SYS_PROTECT`'s new `RESERVE_DISCARD`, which gives
the pages back and keeps their access. `MAP_FIXED` works over the
process's own reservations and nowhere else (`ENOMEM`).

On W2's reservations: `mmap` of anonymous memory (`MAP_PRIVATE |
MAP_ANONYMOUS`, `PROT_NONE` reserving only), `munmap`, `mprotect`,
`madvise(MADV_DONTNEED)` (released and committed again), `sysconf
(_SC_PAGESIZE)`. **`PROT_WRITE | PROT_EXEC` is refused**, as
`SYS_PROTECT` refuses it; JavaScriptCore's two-mapping heap uses
`kosmos_mem_map_rx` through its Kosmos file. `mmap` of a file: not in W3,
since nothing asked yet.

**Test**: in `posixtest.elf` - 4 GB mapped `PROT_NONE`, a page made
readable and writable and used, `mprotect` to read only, `munmap` of a
middle piece and the two ends still usable, `MADV_DONTNEED` reading zero.

## W3c - time and the rest that touches nothing

*Built 11 November 2026* (`testing.md` 18.770), with two corrections to
what is below. **`getenv` stays NULL**: there is no environment, a
recorded position (`user/init/misc_user.c`), and nothing a port needs
depends on one. **`getrandom` is on the libc's `arc4random_buf`**, the
door to the kernel's entropy that already existed, not on the Crypto
Kit's generator. And `getpid` needed `SYS_SELF`, the caller's id as the
process table shows it.

`clock_gettime` (`MONOTONIC` from the counter, `REALTIME` from the epoch
server's answer the process was given), `nanosleep`, `gettimeofday`,
`getenv` over the environment the process was started with, `getpid`,
`sysconf(_SC_NPROCESSORS_ONLN)`, `uname`, `getrandom` on `SYS_ENTROPY`'s
generator in the Crypto Kit.

## W3d - descriptors and files

**The question is here, and it is Diego's.** A descriptor is an index
into a table private to the process; `open` resolves against the process's
namespace and fails where nothing is mounted. But **the namespace is a Lua
kit** (`new_namespace`, `init.lua`): the mount table, and the code that
turns `open` into a request to `/Home`'s disk server, a `/Temporary` ram
server or `/Kosmos`'s binfs, are Lua. A C++ engine's threads cannot call
into it - Lua is not re-entrant across threads, and JetSki's web-content
process has no Lua loop to ask.

Two ways (see *What is Diego's to decide*):

- **A Storage Kit in C** (`user/kits/storage/`): the client side of
  `diskproto.h`, `ramproto.h` and `binproto.h`, safe from any thread,
  handed the mount table - each prefix, its capability, its root and its
  protocol - by the process's runner when it starts. The Lua namespace
  keeps the policy, what is mounted where; the per-call encoding is C.
  `netclient.c` is the same shape already, handed `/Network`'s capability.
  **And then the Lua namespace's own `disk_request` and `ram` paths move
  onto the kit**, so there is one door to each server's protocol rather
  than one in each language - the premise's rule, not an option.
- **Ask Lua**: file calls from C threads go over a ring to the process's
  Lua side, which answers through the namespace as it does today. One
  copy and no kit, but every file operation of every WebKit thread waits
  behind one Lua loop and its collector, and a web-content process would
  have to run one to serve them.

The recommendation is the first. The second puts a garbage collector on
the path of every read SQLite and the disk cache make, which is the
`CLAUDE.md` *Language split* argument exactly.

Either way the calls are: `open`, `close`, `read`, `write`, `pread`,
`pwrite`, `lseek`, `fstat`, `stat`, `ftruncate`, `fsync`, `unlink`,
`rename`, `mkdir`, `rmdir`, `opendir`, `readdir`, `closedir`, `access`,
`realpath`, `getcwd` (the process's start directory), and `stdio` on top
of them, replacing today's read-only `fopen` of what `kosmos_provide`
named. `pipe` is two descriptors over a ring inside the process.

### W3d, as it is being built (11 November 2026)

What exists, read before designing (`diskproto.h`, `ramproto.h`,
`binproto.h`, `init.lua`'s `new_namespace`): **no server hands out a
handle** - every request carries its path; `/Home` speaks `diskproto`
(1024 bytes inline, or a region), `/Temporary` `ramproto` (1024 inline,
or a region; writing at offset 0 truncates), `/Kosmos/*` `binproto`
(read only, 1632 inline, a path of 63 bytes with its root); **the mount
table is a Lua array** and nothing in C can see it; and **`diskask.c` is
already a C client of `diskproto`**, shared by six servers - the kit uses
it rather than being a second one. Four steps:

- **d1, the Storage Kit**, built in 0.11.376 (`testing.md` 18.771)
  (`user/kits/storage/`, `storage.h`): the mount
  table handed to it once by the runner (`sys.storage_start`, each mount's
  prefix, capability, root and protocol, and the working directory), and
  by path - `stat`, read and write at an offset, truncate, list a
  directory a page at a time, make a directory, delete, rename within a
  mount, flush - in `/Home`, `/Temporary` and `/Kosmos`. Safe from any
  thread: the table is written once before the program runs and never
  again, and every call's messages are its own. Errors are the kit's own
  (`STORAGE_ERR_*`), not `errno`. **And `ramproto` gains two flags**,
  `RAM_KEEP` (written at an offset, 0 included, without truncating) and
  `RAM_CUT` (the value ends where these bytes end), because POSIX's
  `write` at 0 must not truncate and `ftruncate` must exist.
- **d2, descriptors** on the kit: a table private to the process, under
  a lock; `open` (with `O_CREAT`, `O_EXCL`, `O_TRUNC`, `O_APPEND`),
  `close`, `read`, `write`, `pread`, `pwrite`, `lseek`, `fstat`, `stat`,
  `ftruncate`, `fsync`, `unlink`, `rename`, `mkdir`, `rmdir`, `access`,
  `opendir`, `readdir`, `closedir`, `realpath`, `getcwd`, `fcntl`'s flags.
- **d3, `stdio` for ported code** over descriptors, in place of the
  runtime's read-only `fopen` of what `kosmos_provide` named - which the
  rest of the system uses and keeps.
- **d4, one door**: the Lua namespace's `disk_request` and `ram_request`
  encoding moved onto the kit.

Reads go 1024 bytes a message to begin with; a region for large reads
comes when a measurement says the messages are where the time goes.

### W3d2, as it is being built

Descriptors, in `runtime/posix/fd.c`, on the Storage Kit. What was found
before writing it:

- **A descriptor is a path and an offset.** No server hands out a
  handle, so an open file is the whole path, made absolute when it was
  opened, the position, and the flags it was opened with, in a table
  private to the process under one mutex. `dup` shares an entry, as
  POSIX's shared offset requires; the table grows and never shrinks. A
  file renamed or deleted under an open descriptor is lost to it, which
  a server with handles would not do: recorded, not hidden.
- **0, 1 and 2 are the console.** A write to 1 or 2 is `kosmos_write`,
  as `printf` is; a read of 0 is end of file - a ported library does not
  read a person's keys.
- **`O_EXCL` is asked, then made**: a stat and a create, two requests,
  so two processes making one file at once can both succeed. No server
  can make a file only if it is not there; a `RAM_EXCL` and a
  `DISK_EXCL` are the cure, when something needs them.
- **The runtime's failing `mkdir` (`misc_user.c`) and `isatty`
  (`stdio.c`) become weak**, so the layer's own win where it is linked
  and every image without it keeps what it has. And `fcntl.h` and
  `sys/stat.h` in `runtime/include/` said there would never be an `open`
  or a `stat`: true of the runtime and of Kosmos's own code still, and
  rewritten to say where the ported code's are.
- **No `chdir`** yet: the working directory is the one the program was
  started in. Nothing in WebKit or curl's path needs another.

## W3e - sockets

`socket` (`AF_INET`, `SOCK_STREAM`, and `SOCK_DGRAM` for DNS),
`connect`, `send`, `recv`, `shutdown`, `close`, `getaddrinfo` on
`net_client_resolve`, `getsockopt`/`setsockopt` for the handful curl sets,
non-blocking descriptors with `fcntl(O_NONBLOCK)`, and `poll` over sockets
and pipes together, on `net_client_poll`. All of it on the Network Kit's
`netclient.c`, which a C thread can already use with `/Network`'s
capability - so sockets need no decision beyond W3d's: the capability
comes to C the same way the mount table does. `listen` and `accept` are
there, because `netclient.c` has them.

**Test**: `posixtest.elf` fetching a page from the gate's own web server
(`x86-servers`' one) with plain sockets, `poll` across two connections at
once, and curl's own `curl_easy_perform` against it once curl is vendored
(W5).
