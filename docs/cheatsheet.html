Kosmos

The prompt, as a place to work. The same page is in the machine: type help "shell" - and the quotes are not decoration, which is explained at the bottom.

The line you are typing

  • up and down - the lines typed before, thirty-two of them
  • backspace - the only editing there is; there is no cursor
  • Control-C - abandon the line and start a fresh one

Moving around

  • pwd - where you are
  • cd path - somewhere else; cd alone goes to /
  • ls path - one level
  • tree path - all of them, from here down

Reading

  • cat path - the whole thing; a value, so a table prints as one
  • head -n 5 path - the first lines, ten by default
  • tail -n 5 path - the last ones
  • wc path - lines, words and bytes
  • grep pattern path - the lines that match, with their numbers
  • du path - how much is under each directory in here

Changing

  • touch path - an empty file
  • mkdir path - one directory, no -p
  • cp from to - a directory as the destination means "into it"
  • mv from to - rename and move are the same operation
  • rm -r path - -r is the program walking, not a flag a server has
  • save path text - write a line and read it back
  • edit path - the editor, in a window

What a file is, rather than what is in it

  • stat path - kind, size, and where the bytes are
  • which name - where a program is, if it is anywhere
  • attr path - its attributes
  • attr path kind=note - set one
  • find kind=note - everything that matches, anywhere that can answer

The desktop

  • /home/Desktop - what the desktop shows, and nothing else
  • launcher path program args - an icon that starts a program; Drive is tracker /
  • attr path on a desktop icon - desktop_x and desktop_y are where it was dragged
  • Trash - Delete puts things here; Empty Trash, in a Tracker window's File menu, is the one that does not come back

The machine

  • ps - what is running, with an id and a band each
  • kill id or name - end one; two of a name is a refusal, not a guess
  • df - what each mount holds, and what the disk has left
  • neofetch - the short answer
  • machine - the long one, including what it cannot be asked
  • mem and cpu - memory, processors
  • devices - every device, and whether a driver claimed it
  • diskinfo - what is on the disk

Where things live

  • /bin /lib - the programs and libraries in the image
  • /home /user /system - the disk; these survive a reboot
  • /ramfs - memory; this does not
  • /dev /net /app - devices, the network, the running applications

/ is not a filesystem. It is a list of mounts, each answered by a different server, and ls / shows exactly the ones the process asking was handed.

Two rules that will catch you

A line with Lua punctuation in it is Lua, not a command. grep [ f is evaluated and fails; /grep [ f runs the program. The same rule is why help fs is a syntax error while help "fs" and /help fs both work - help names a value in the shell, so a bare word naming it goes to Lua.

There are no pipes and no redirection. The bar and the angle bracket are not spelled differently here, they are absent - a shell that composed programs that way needs a stream between two processes, and what this system has between processes is messages and shared memory.

Deliberately missing

chmod, chown, sudo, useradd - there are no users and no permission bits. What you may reach is decided by the capabilities you were handed, which is not something a command can change.

man is help. ln - no links in the filesystem. hostname - nothing here has a global name. env and export - no environment variables. sort, cut, sed, awk, tee - pipeline tools, and there are no pipes yet.

/commands lists the words the shell answers to itself.
