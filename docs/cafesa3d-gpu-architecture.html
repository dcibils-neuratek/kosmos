Cafesa3D on the GPU - what it stands on

The ray tracer, written once in Kosmos's own kernel language and compiled on Kosmos to the GPU's assembly; the scene packed into Compute Kit buffers by the 3D Kit; each pass one message. The driver checks whatever the compiler writes, so the compiler is never trusted with the GPU's safety. An emulator on the Mac runs every kernel in make test, where there is no GPU. Recommended answers to E1-E4 drawn; cafesa3d-gpu.md has the others.

P - a pass of the Rendered view

  1. P0 once a scene: the tracer compiled and assembled, the scene packed into buffers.
  2. P1 the camera, the pass, the bounces into the run's constants.
  3. P2 compute.run: one message, 160 × 720 groups of eight pixels.
  4. P3 the driver: the state page, the walker, the fence - as GPU Fractal's.
  5. P4 each lane walks the tree of boxes for its ray, its stack in a buffer.
  6. P5 shading, a shadow ray to each lamp, the bounces.
  7. P6 the sample added in; a second run makes the colours.
  8. P7 the ticket asked on Cafesa3D's clock; the view shows the picture as it is.
