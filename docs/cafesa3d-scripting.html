What a script can reach

The scene and nothing else. A script runs in a Lua environment of its own, made fresh for each Run, holding the calls below, Lua's own math, string and table, and print, whose lines go to the strip under the code. There is no fs, no sys, no use, no network and no other window - what a script was not handed it cannot reach, as everywhere else in Kosmos.

CallWhat it makes, and what it takes
scene.box{ ... }A box: size = { x, y, z }. And scene.plane, scene.sphere, scene.ico, scene.cylinder, scene.cone, scene.torus, scene.grid - each with the numbers its Data tab shows, by the same names: radius, depth, segments, rings and the rest.
every shape alsoname, loc, rot in degrees, scale, smooth, hidden, and material = { preset, base, metallic, rough, trans, ior, emit, texture, colour2, texture_scale, bump } - the Material tab's fields, by its names.
scene.mesh{ ... }Triangles of the script's own: points = { {x, y, z}, ... } and faces = { {1, 2, 3}, ... }, with smooth_angle. And three makers of them, the ones the samples are built with: shapes.lathe(profile, segments), shapes.loft(rings) and shapes.bevel(box, radius).
scene.light{ ... }A lamp: loc, power, radius, colour.
scene.camera{ ... }Moves the camera: loc, target, focal. There is one camera.
scene.world{ ... }The sky: zenith, horizon, strength.
scene.find(name)An object already in the scene, to read or move: find("Ground").loc. What a script changes this way is its to change back on the next Run.

Every call is held to what the Properties tabs hold a number to, and a wrong name or value is refused with a sentence and the line - "Line 13: the texture Wod is not one of None, Checker, Brick, Tiles, Noise, Wood, Marble". Colours are written as 0xrrggbb, the way the file keeps them.

What a Run does

All or nothing, and one undo step. The script runs to its end before the scene is touched; a mistake anywhere leaves the scene as it was and marks the line. Ctrl Z takes back a whole Run, as it takes back any other change.

A Run replaces what the last one made. Objects a script makes are its own - the Outliner groups them under its name - so changing a number and pressing Run again gives the new staircase instead of a second one on top of the first. Objects made by hand are never touched.

A loop that never ends is stopped, after a few seconds' worth of instructions, with nothing it made kept - Cafesa3D stays answering, because a script is counted as it runs rather than trusted to finish.

Saved with the scene. The script goes in the scene's file, so opening it brings back the code with what it made. Open .lua... and Save .lua... take a script on its own, to share or keep. (The house, the car and the plane stay glTF files for now - Diego, 27 September.)

Yours to decide

  • Where the panel sits - beside the view, as drawn, which suits your 3440-wide screen; or under it, which suits a narrow one. It could follow the window's shape.
  • Whether a Run replaces what the last one made (as drawn) or adds to the scene every time, which is Blender's way. Replacing is what makes changing a number and running again feel like turning a knob.
  • One script a scene, or several, each with its name as a tab along the panel's top.
  • Running as you type, a moment after you stop, as well as on Ctrl Enter - lively for a staircase, too eager for a script that builds a city.
  • The key that opens the panel: Shift F4 is drawn, beside Blender's Shift F11 for its text editor, since F11 is full screen here.
