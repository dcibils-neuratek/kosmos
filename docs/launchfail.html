When an application does not start

The window Astra shows in place of the application that could not open: what went wrong in a person's words, the system's own words beneath them, and what to do about it as a button where there is one. Drawn on 22 November 2026, before any of it is built. For Diego to change until it is right.

Diego, 22 November, after Quake III and Flight would not open on the M700: "and also it does not say why", "we should show a window with the error message for me to understand why is not working".

Made for another Kosmos

The case that happened tonight. Update installs the server's copy (the same as pkg install quake3) and opens it when that is done; the window shows the download as it goes, and closes itself when the application's own window appears. The protocol numbers are kept for a report, in the system's words, beneath the person's.

Made for another Kosmos, with nowhere to update from

A machine booted from a stick has no package server. Update is not offered; the sentence says what will fix it instead.

Anything else

Every other reason a start fails gets the same window, with the reason it was given. One that stops in its first moments (a crash before its window opened) offers Show the log, which opens Log View at that program's lines. The left window: a program whose file is gone. The right: one that stopped by itself before it drew.

Left out, on purpose

  • A window for every failure in the background. Only a start a person asked for, from the Deskbar, the dock, the launcher pad, Tracker or open. A program a script starts says its failure to the script.
  • Updating without asking. At boot that is P5's job, and it says what it did. Here the person asked to open something, and is asked before a download.
