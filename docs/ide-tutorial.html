Kosmos IDE Tutorial

Fourteen lessons that build real apps in the IDE, from a button to 3D: first in Lua, then with C. Each one ends by opening the bundled Kosmos app that does the same thing for real, so the system's own apps become the worked examples. Planned here to be agreed before any lesson is written.

How a lesson works

A page and a project. Each lesson is a page with pictures, taken in QEMU by a tool so they can be retaken when an app changes. It comes with a small project that is complete at every step. Open it from the IDE's Help menu: Tutorial shows the contents in the browser, and each lesson's Open this lesson's project copies its folder into /Home/development/ and opens it in the IDE.

Every lesson has the same four parts: what you build, the steps with the code, "try changing", and How Kosmos does it, which names the kits, servers and drivers involved. The worked example is the bundled app that does the same thing; the IDE opens its source, and you can save a copy to change.

Every lesson is tested. A suite builds and runs every lesson project on both processors, as the templates are, so a lesson can't quietly stop working.

9. A window from C

Plasma is a C app with a window of its own: the animation, the keys and the pointer are all C. Its one line of Lua only starts it.

Open this lesson's project

The IDE with plasma.c open, the Output panel saying "built build/plasma.elf"

F6 builds plasma.c into build/plasma.elf in about a quarter of a second.

Open a window

/* A window that draws its own pixels, 480 by 300, which can be resized. */
struct kw_window *w = kw_open("Plasma", 480, 300, KW_RESIZABLE | KW_CENTRE);

Draw a frame, then show it

struct kw_surface s = kw_surface(w);       /* pixels, width, height, pitch */
draw(s.pixels, s.width, s.height, s.pitch);
kw_commit(w, 0, 0, s.width, s.height);    /* this buffer is shown now */
Plasma's window on the desktop

F5 runs it.

Try changing

Make Space change the speed instead of pausing, or draw the plasma in four colours only.

How Kosmos does it. The window's pixels are a region shared with the window manager, holding two buffers. kw_commit swaps which one is shown, so nothing is copied. Each frame is one fixed-size message to the window manager, so the app makes no garbage at all.

The real thing: the Plasma template. Help ▸ Kits and their calls ▸ window lists all five calls.

What's yours to decide

  1. The fourteen lessons, in four parts, as listed. Recommended as drawn: button to 3D, as agreed in September, with C as part three now that the IDE builds it.
  2. Where it opens: the IDE's Help ▸ Tutorial, pages in the browser like Cafesa3D's tutorial, each lesson's project copied into /Home/development/. Recommended.
  3. The bundled apps as worked examples open read-only in the IDE, with Save a copy to change one. Or open them straight for editing, which changes the system's own app. Recommended: read-only with a copy, until installed apps can be replaced safely.
  4. The order of building: one part at a time, each shown to you before the next. Part one first, together with the Help menu and the lesson suite. Recommended.
