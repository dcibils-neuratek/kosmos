Xavier

An assistant that answers in a window and aloud, run on this machine, on a language model the LLM server holds. Type a question or hold a key and say it, and the answer is written a word at a time and, if you want, read out. Each conversation is a file in /Home/Xavier. The window's foot says what each answer cost and where it ran. Models come from Hugging Face with models, and what the engine is doing is a window of its own. In later versions Xavier does things, each one shown and confirmed first.

Diego, 8 November 2026: "a chat and audio interface to chat with Xavier to general questions and answers and in the following versions, do stuff in the OS like write an email, open settings, open files and else", "a way to load models from huggingface easily", "a way yo see LLM inference engine metrics like models loaded, usage, tokens per second, etc" - and, for this page, "I need to see the mockup of the Xavier app".

The first answer, about Paris, is what the LLM Kit wrote on the Mac under X1, word for word; the rest of the words on this page are written to show the window. Every speed on this page is an illustration until X3 measures one on Kosmos.

On the left, the conversations, newest first. Each is a file in /Home/Xavier that opens again where it was left and goes to the Trash like anything else. In the middle, the conversation: your words on the right, Xavier's on the left, written as they arrive, with a block of code drawn as code. Stop ends an answer where it is. Hold the mic button, or Space with the question box empty, and speak. What is heard appears as you say it, and becomes the question when you let go, marked heard so a mishearing is visible. The answer is written and read out a sentence at a time, the reading starting as the first sentence is done. Silence stops the voice and leaves the words. This needs a microphone driver, a speech-to-text model and a voice, none of which exist yet (xavier.md X6-X7, and decision 5).

A system key opens a box over whatever is in front, as the launcher pad opens. Ask, read the answer, Esc, and you are back where you were; Tab carries the conversation into the window. Which key it is goes into shortcuts.md with the others. The date in the answer is something the model cannot know: Xavier tells it the date, the machine and the user's name at the start of every conversation, which is a few lines of the prompt, not a tool.

What is on the disk first, then a search of Hugging Face's public API, listing only repositories that publish GGUF. A download resumes where it was cut and is held to the SHA-256 that Hugging Face lists for the file before it can be loaded. A file Kosmos cannot run is listed with the reason, not a Load button: a kind of model the kit has no forward pass for, or a quantisation it does not read. A model published only as safetensors, phi-2 itself among them, is converted on the Mac by tools/hfmodel.py, because converting needs PyTorch. The model names here are real repositories, but which of them Kosmos will run is decided by X8b.

Xavier is opened on a project and reaches that folder and nothing else - a capability, not a promise. It reads the files it needs and says so under its answer. A change is a diff, file by file, with Accept and Refuse on each; nothing is written that a person has not accepted. Running a program or a test is a step of its own and asked first; its output is read back, and a failure becomes the next proposal. The model is one trained for code and for calling tools, with room to hold a file - Qwen2.5-Coder, not phi-2. The project, the bug and the edit are written to show the window.

Xavier itself is Lua and thin: the window, the files, and calls. The model's arithmetic is C in the kit. The words arrive in the window as messages, a few bytes each, because a token is something somebody asked for and not something a clock sends. The weights and the cache stay in the server's memory and never cross to the application.
