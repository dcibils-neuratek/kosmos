What is drawn

New Project asks the kind first - Lua, Lua and C, C - with what each is for, and offers its templates: each builds and runs as it is. Diego's three kinds, in his words.
Build (F6) compiles the C with TinyCC and links it with Kosmos's runtime into the project's image. Its errors are the Problems the IDE already lists, each a click from its line. A build that fails writes nothing.
Run (F5) builds first when a C file changed, then starts the Lua inside the image - -- kosmos: image, as Doom is. A change to the Lua alone builds nothing.
The image is made, not written: greyed in the tree, with its size. It is a whole program, so the project folder can be copied to another Kosmos and run there.
tcc is the same compiler at the prompt - in a Terminal, over telnet, after editing in Write.
Not drawn: a C app with a window of its own (question 2 in docs/tinycc.md), and a debugger, which is later.
