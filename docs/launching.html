An application starting

From the click to its first window, on the Deskbar. Diego, 29 September 2026: “When launching an app we do need some indicator of the app loading” — otherwise “the user might think it didn’t actually launch and might try again, triggering a double launch”. An installed application now starts in the background (testing.md 18.275), so the desktop keeps moving; what it does not yet do is say anything until the window arrives. Three ways to say it, animated below, and the behaviour under all three.

In all three the title is dimmed while the program starts, and the button is where it will stay: the window’s own button takes its place, so nothing jumps. B is recommended because it is the one a person already knows; in a bar 32 pixels tall the hop is four pixels. With reduced motion asked for, each holds still at half strength.

What it settles

QuestionAnswer
A second click while it starts Starts nothing. The window manager refuses a second start of a program that is still starting, from the Deskbar, a desktop icon, Tracker or anything else that asks it; the click is taken as “yes, it is coming”. Once the first window is open, starting another is what it always was.
A program that never opens a window Its button goes after twenty seconds, or when its process ends, whichever is first.
What knows it is starting The window manager: it lists starting programs beside its windows, and tells the Deskbar when that list changes as it does for windows. The Deskbar draws; it keeps no second memory beyond the moment between the click and the answer.
Applications in the system’s image The same, and usually too quick to see: under QEMU the window manager answers Calculator’s start in 60 ms. On the M700 an installed game is the one it is for.
