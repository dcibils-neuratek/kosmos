Tracker's right click

Drawn on 27 September 2026, before any of it is built — roadmap.md 6za, 6z and 6v, on one page because they are one menu. Diego, on the M700 with 0.10.174: “A context menu on right click should appear on the folder and give me options” — pin to sidebar, compress, info. Today the right button opens the same eleven items whatever it was pressed on, which is how a folder in Home came to offer Edit and Empty Trash.

What the right button offers, by what it was pressed on

The menu offers what applies to what was clicked and nothing else. Items marked NEW are new; everything else is in Tracker now. The ⋮ menu in the header is unchanged and still holds all of them.

Pin to sidebar

A pinned folder is a place, and places already exist: one small file each in /Home/Places, drawn in the sidebar after Home and Desktop, made today by dragging a folder or a drive there (/Kosmos/Libraries/places.lua). Pin to sidebar is that same file made from the menu, so the two ways agree by construction. Unpin removes the place and never the folder.

Pins come after the places every home has — Documents, Photos, Movies, Captures and Music (6w) — in the order they were pinned, so the standard ones stay where the hand expects them.

Compress and Extract

Compress makes a .zip beside what was clicked, named after it: roms becomes roms.zip. Several things at once make Archive.zip. A name already taken gets a number, roms 2.zip, the way New folder already picks new folder 2. Extract does the reverse into a folder named after the zip.

The zip is drawn as it is being written, shaded until it is finished, so the window says where it will be before it is done. The progress sits in the window's foot, where Tracker already writes what it did. The window keeps working while it runs: the work is a program of its own (question 3). Info

A small window of its own, one per thing asked about, which opens at once with what Tracker already knows and fills in what has to be counted. A folder's size is everything inside it, counted by walking it, with how many files and folders that was.

* Modified is not free, and this is the part of Info that is real work. A file in /Home is stamped with the counter since the machine started, not a date — so after a restart the number means nothing, and that is why Tracker has no Modified column today (the comment at the top of tracker.lua says so). The clock exists, /Devices/clock. The disk server was never given it. Giving it that, and stamping real dates, is a step of its own before Info. Files written before then show no date rather than a wrong one. There is no Created line: kfs keeps one time for a file, and a second is a format change that nothing else needs.

Open with, and File types in Preferences

Which application opens a type is one setting, shown where it is looked for: in Preferences' new File types page, and on every file's Info. Both change the same thing. Open with ▸ in the right click is for this once and changes nothing.

Preferences
File types

A type only one application opens shows its name, not a choice. The rows come from the applications themselves, below. What is written to /Home/Preferences is only a choice that differs from the default, so a home carried to another machine takes its choices with it and nothing else.

Where the list comes from

An application says what it opens in its own header, as it already says its icon. The header is the manifest (6t). binfs reports it as it reports needs, and filetypes gathers the answer from /Kosmos/Apps, and from /Home/Apps once applications live there. The table written by hand in filetypes.lua goes. Installing an application adds its types, and deleting it takes them away.

Where two applications open a type and nobody has chosen, the one in /Kosmos/Apps is the default. After that, it is the first by name, so the answer never depends on the order in which things were found.

Seven things to decide

Each one is drawn above as recommended. Answer by number, as before.

  1. A zip opens by extracting. Double-click and Extract both put its contents in a folder beside it, named after it, and open that folder.

    Looking inside a zip without extracting it, as a folder you can browse, is a bigger thing (a zip served as a mount) and can come later if it is wanted.

  2. Several things compress into Archive.zip, and a taken name gets a number.

    The alternative is naming it after the folder they are in. Archive says what it is when it turns up somewhere else.

  3. The work runs as a program of its own, zip and unzip, which Tracker starts and watches.

    Tracker is one Lua loop. Compressing two gigabytes inside it would freeze the window until it finished, and threads in a process are not built yet. As a program, the window keeps answering, Stop is ending a process, and the prompt gets the same two programs for free.

  4. DEFLATE from miniz, vendored into the compress kit beside the inflater it already has.

    miniz is one C file that compresses, inflates, and reads and writes zips. The kit gains deflate and zip reading and writing. Writing our own compressor is the alternative, and a project in its own right.

  5. The disk server gets the clock, and files get real dates, as a step before Info.

    Without it, Info has no Modified line and Tracker can never have a Modified column. The stamp moves from sys.ticks() to /Devices/clock's time; the format has room for it already.

  6. Pins go after Documents, Photos, Movies, Captures and Music, in the order pinned.

    Or straight after Desktop, above the standard ones, if a pin should come first.

  7. Applications declare what they open in their header (-- kosmos: opens mp4), and the default for a type is one setting, shown in Preferences and in Info.

    Open with in the menu picks for this once only. Asking “always?” there would be a third place to change it.
