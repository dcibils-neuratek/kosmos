USB audio - what it stands on

A USB speaker is one more place for the mix to go, not a second mixer. Programs write to their rings as they do now and never learn which device plays. The audio server mixes, converts to the device's format and writes periods into a ring; the USB driver feeds the speaker's isochronous endpoint from it, at the speaker's clock. A period (P) never leaves C; Mixer (U) only lists and chooses.

P - a period

  1. P1 A program writes 256 frames to its ring and says nothing.
  2. P2 The server, woken by xhci's "room", sums every stream with its gain.
  3. P3 44.1 kHz to 48 kHz, 16 bits to the device's: one pass, in C, vectorised.
  4. P4 Into the USB ring; a pulse to xhci.
  5. P5 xhci copies the next millisecond, 192 bytes, into the TD the controller needs next. The speaker's clock sets the pace.

U - a speaker plugged in

  1. U1 xhci enumerates it, as any device, and sees an Audio Streaming interface.
  2. U2 uac_decode.c reads what it offers; xhci tells the server, with the ring's region.
  3. U3 The server adds it; if it was the one chosen last, the mix moves there. A notification names it.
  4. U4 Mixer, watching, is pulsed and redraws.
