The window only shows and asks. RFB is one kit, rfb.lua, which vncd moves onto as well, so the protocol exists once. The picture never becomes a Lua value: from the connection's ring to the window's surface it goes through three kits' C, region to region, and Lua carries only offsets, lengths and twelve-byte headers.

F - a frame from the Mac

  1. F1 the Mac's bytes land in the connection's ring in net, which wakes the window.
  2. F2 read_into copies them into a region of the window's process.
  3. F3 rfb.lua reads each rectangle's twelve-byte header and ZRLE's length.
  4. F4 inflate turns the zlib stream into ZRLE's tiles, in a second region.
  5. F5 zrle_decode writes the tiles' pixels into the remote screen's surface.
  6. F6 the changed rectangle drawn fitted into the window and committed as damage; the next update asked for.
