Network Monitor - what it stands on

It counts nothing itself: the network server counts every frame in and out, in total and on each connection, and answers one new request; the kernel says which program opened a connection; the graph is Monitor's, moved into the kit. Network Monitor asks once a pace and draws.

Servers and drivers

NEWnetwork server - net.c

counts each frame's bytes and the packet, in total and on its connection F2; NET_OP_STATS, a declared shape in netproto.h: the totals, dropped, and a page of connections - each its process, where it goes, its state, its bytes each way W1

Nebula

NEWSYS_SENDER

the process behind a reply token a server holds - asked once, when a connection is opened. A process id is in sys.processes() already; this names only a server's own callers.

IPC, regions

the frame ring between driver and server

F - a frame

  1. F1 The driver hands the frame through its ring, as now.
  2. F2 The server adds its length to the total and to its connection, and counts the packet - two or three additions on a path that already copies the frame.

W - the window, once a pace

  1. W1 One NET_OP_STATS: the totals and the first page of connections.
  2. W2 The programs' names, from their ids.
  3. W3 Rates as the difference between this reading and the last.
  4. W4 A column on the graph, the list sorted by what is busiest, a paint.
