What each moment shows

Preview NEW The app runs in its own process, as Run runs it today; the window manager draws its window inside the IDE's right pane rather than on the desktop. Saving restarts it in place. Resting on a control names it from what Automations already publishes, and a click puts the editor on the line that made it. Light and Dark switch the app's look without touching Preferences. Signature help and the problem's words at the end of its line are in the editor.

Debugging NEW A breakpoint at line 16 was hit. The bar over the editor has Continue and the three steps; the Debug pane has the stack - a Kosmos library's frame shown, read only - the locals, the upvalues opened a level, and a watch. The Console evaluates in the frame chosen. The app is paused and its window in the preview says so.

Profiling NEW A planet simulation, Orbits, with sound. Each frame a bar against 16.7 ms, the collector's in orange; where the time went by layer, from Nebula's sampling; the Lua functions by their own time and what they allocate; and the hottest lines' share in the gutter, so pull making a table per pair is in front of you.

New Project GROWS By what you are making. Each template runs as it is, shows what it looks like, and names the kits it stands on - so the Sound template is also a way to learn the Playback Kit. One that needs a power says so in orange.

Layout NEW main.form opened in Design. The canvas is the real window, hosted as the preview is; a slider is being dragged in from the palette, with the guides at the kit's spacing. Properties set the name the code uses, the words, the place and the edges it follows; on_change is a link to where the code sets it.

What's yours to decide

  1. The preview inside the IDE's window, hosted by the window manager. Recommended. The app's own window kept beside the IDE needs nothing new, and loses the one window.
  2. A restart on save, not a reload that keeps the app's state. Recommended. ui.keep later, if a restart loses too much.
  3. The debugger reaches only programs the IDE started. Recommended: that is the capability.
  4. Layouts as form files, which the code loads and names. Recommended.
  5. A program in /Home asks once for its powers when the IDE runs it. Recommended.
  6. History now, Git when its client is designed. Recommended.
  7. The tutorial in a pane of the IDE. Recommended.
  8. The order: the loop first, then knowing the code, then the debugger and profiler. Recommended.
  9. The kit's name, the Inspect Kit. Recommended.

Each is argued in docs/ide.md, Yours to decide.
