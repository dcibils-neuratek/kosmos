A 3D API for Kosmos - what it stands on

Vulkan is the contract every GPU driver supplies, and Mesa supplies it; GL and GL ES come from Zink on top, so there is one GL on every machine. Mesa runs in each program's own process and meets Kosmos at its KMD seam, speaking a declared protocol to intelgpu - no ioctl, no DRM shim. lavapipe gives the whole API in QEMU first; on the M700 only the bottom changes. Nebula gains nothing. Recommended answers drawn; gpu3d.md has the others.

F - a frame on the M700

  1. F1 the program records; Mesa writes the batch into a region bound in its context.
  2. F2 vkQueueSubmit: one message, GPU_OP_EXEC - where the batch is, the waits, the value to signal. Answered at once.
  3. F3 the context on the submission port; the GPU draws into the swapchain image, in the program's own address space.
  4. F4 the fence page written, the interrupt; a pulse to whoever waits.
  5. F5 vkQueuePresentKHR: one message to the window manager, the image and its fence.
  6. F6 the GPU compositor samples it at the next refresh - or a full-screen game's image is flipped.
