# W5 - the libraries WebCore stands on

JetSki's fifth step (`docs/webkit.md`): every library WebCore links,
built for Kosmos and each one shown working on its own before W6 asks
WebCore to draw a page with them. Written 12 November 2026, before any
of it was built; W5a to W5e are built.

**What W4 left.** JavaScriptCore runs, with ICU, WTF and bmalloc under it,
and test262 counts it (`docs/w4.md`). The POSIX layer, the C++ runtime and
`tools/upstream.py`'s fetching are in place.

**What W6 needs**, from `webkit.md`'s port table (Windows' drawing and
network, PlayStation's choices about the JIT and the GPU): FreeType and
HarfBuzz for text, libpng, libjpeg-turbo and libwebp for pictures, SQLite
for storage, libxml2 for XML, libpsl for cookies' domains, curl and OpenSSL
for the network, zlib under most of them, and Skia, which WebKit carries
in `Source/ThirdParty/skia`.

---

## What is decided already

`webkit.md`'s table and *Decided by Diego, 11 November*:

- **The Text Kit is FreeType and HarfBuzz behind one door**, for every
  application that draws text, not only JetSki.
- **Pictures move onto libpng, libjpeg-turbo and libwebp.** `gfx` decodes
  with `stb_image` today, and keeping both would be a second decoder of
  each format. The move is a step of its own after these build, with
  `gfx`'s callers held to the same tests before and after.
- **OpenSSL is the system's one TLS.** curl and WebKit use it, and the TLS
  Kit moves onto it in a step of its own after W5.
- **SQLite holds a site's storage**, in `/Home` through the namespace.

## The steps

Each library is held to its own tests where it ships them, run on this
Mac first and then in the guest as an installed `*test.elf`, as `icutest`
and `wtftest` are. Every test has a control.

| step | what | held to |
|---|---|---|
| **W5a** | zlib, libpng, libjpeg-turbo, libwebp | each library's own test pictures, decoded in the guest and compared byte for byte with the same library on this Mac |
| **W5b** | FreeType and HarfBuzz: the Text Kit's engines | HarfBuzz's own shaping suite - 7,761 cases in every script it ships fonts for - each held to the glyphs it expects, and FreeType rendering every font in it; every line the same as on this Mac |
| **W5c** | SQLite, libxml2, libpsl | SQLite's own `fuzzcheck` and `speedtest1`, which need no Tcl, the dotfile lock, a database written to `/Home` and read back after a reboot; libxml2's own `runtest` over its test trees; libpsl's own five tests |
| **W5d** | OpenSSL and curl | OpenSSL's tests that run without a shell; curl fetching a page over HTTPS from inside the guest, from the host's test server, as `x86-network`'s checks do |
| **W5e** | Skia, from WebKit's own copy | a scene of paths, gradients, text through the Text Kit and a picture, drawn by Skia in the guest and compared with the same Skia on this Mac |

## W5a - built, 0.11.386

**zlib 1.4, libpng 1.6.59, libjpeg-turbo 3.2.1 and libwebp 1.6.0**, each
fetched and held to what its publisher gives (`tools/upstream.py`):
GitHub's digests for zlib's and libjpeg-turbo's release tarballs, and for
libpng and libwebp - whose releases are tags, with no asset GitHub keeps a
digest for - the tag's commit, fetched as test262 is and refused unless git
says that is what it holds. `tools/w5_build.py` builds each with its own
CMake into a static library, for Kosmos through `runtime/cxx/kosmos.cmake`
and for this Mac natively as the reference.

**Each one's vector code is on**, on both processors: libpng's filters in
NEON and SSE2, libjpeg-turbo's NEON and its SSE2 and AVX2 assembled by
`nasm` (fetched from Homebrew for it, 3.1 MB; `REQUIRE_SIMD`, so a build
that fell back to C fails rather than passing slowly), libwebp's NEON,
SSE2 and SSE4.1.

What each library was told, and why, is in `w5_build.py`. Two of them
matter beyond the build:

- **TurboJPEG is off.** libjpeg-turbo's convenience API loads and saves
  PNG files through a libspng and a zlib of its own compiled into it - a
  second PNG reader and a second deflate in the system. WebKit decodes
  through libjpeg's own API, `jpeglib.h`, and that is what is built.
- **`NO_PUTENV`.** Kosmos has no environment (`runtime/posix/process.c`),
  and the only thing libjpeg-turbo would put in one is the old API's
  request that its SIMD pretend to be less.

**Held to:** `tools/run_pictures.py`, the gate's `x86-pictures`.
`picturetest.elf` is given 216 files - every PNG in libpng's tree
(PngSuite, its broken files, its crashers), every picture in
libjpeg-turbo's `testimages`, and libwebp's WebPs - and says 439 lines
about them: each file deflated at three levels and as gzip and inflated
back; each PNG through the simplified API and through the progressive
reader fed 512 bytes at a time, as WebKit feeds a picture still arriving,
with the crashers failing in libpng's own sentences; each JPEG with the
accurate DCT, the fast one and at half size, at 8 and 12 bits;
`testorig.ppm` encoded as PNG, three JPEGs and two WebPs and decoded back.
**Every line is the line the same file says on this Mac**, compiled
natively against the same releases - including the lossy encoders, whose
vector code is NEON there and SSE2 and AVX2 in the guest. 3.7 s in the
guest.

**libwebp's own reference is out of date.** `test_ref.ppm` is what
`doc/tools.md` says `test.webp` decodes to "exactly", and it was written
in 2010; the decoder's conversion from YUV has been made more exact since,
and 13,265 of its values are one away from what 1.6.0 decodes, none
further - on this Mac as in the guest. So `test.webp` is held to within
one of it, and how many differ is part of the line held to the Mac.

**Controls**: one byte in the middle of each of a library's pictures,
turned over for the reference only (`KOSMOS_PICTURES_BREAK=<library>`),
fails the run - libpng 360 lines of 439, libjpeg-turbo 21, libwebp 8 - and
the run passes again without it.

## W5b - built, 0.11.388

**FreeType 2.15.0 and HarfBuzz 15.1.0**, fetched as W5a's are: FreeType's
release is a tag, held to its commit (`37515cf`, VER-2-15-0) from
freedesktop's GitLab; HarfBuzz's tarball to GitHub's digest. Both are built
by `w5_build.py` with their own CMake.

What each was told, and why, is in `w5_build.py`:

- **FreeType reads its PNG glyphs through W5a's libpng and its
  compressed fonts through zlib 1.4** - `FT_REQUIRE_PNG`, `FT_REQUIRE_ZLIB`,
  which fail the configure rather than leaving either out because it was
  not found. Brotli is off because WOFF2 is decoded by WebKit with its own
  copy of Google's, and bzip2 because nothing here is a `.pcf.bz2` X11
  font.
- **HarfBuzz uses FreeType**, so both of its font-functions - its own
  (`ot`) and FreeType's (`ft`) - exist and are tested. Its subsetter,
  rasteriser, vector and GPU libraries and its tools are off: the tools
  need GLib and Cairo, and what is drawn here is drawn by Skia at W5e.
- **FreeType is not told about HarfBuzz** (`FT_DISABLE_HARFBUZZ`):
  HarfBuzz is built after FreeType and on it, so it cannot also be under
  it.

**Three things libm lacked**, each from the same musl 1.2.5 tarball and
its sum: `hypotf` and `roundf`, which HarfBuzz calls and `math.h` did not
declare, and `scalbnf`, which `math.h` declared and nothing defined.

**Held to:** `tools/run_text.py`, the gate's `x86-text`. HarfBuzz's own
suite is `test/shape/run-tests.py` driving `hb-shape`, and `hb-shape` is
built on GLib, so neither runs here. `user/kits/texttest/texttest.c` is
the part of `hb-shape` the suite uses, written from its sources
(`util/shape-options.hh`, `font-options.hh`, `text-options.hh`,
`shape-output.hh`): the same buffer flags, the same font set-up - the size
in font units, ptem, synthetic bold and slant, the named instance and the
variations, the font-functions - the same serialisation, and the second
look `run-tests.py` takes through `--glyphs --no-glyph-names` when only
the glyph names differ.

`run_text.py` reads the `.tests` files HarfBuzz's Meson build names - not
the `disabled_` list beside it - as `run-tests.py` reads them: its
directives, each case once for each font-functions it asks for, the
`--verify --unsafe-to-concat --safe-to-insert-tatweel` added to every case
with an expectation, and the skips. 148 cases are skipped there as they
would be anywhere but a Mac with those fonts: they name macOS's own fonts,
by path and by their SHA-1.

**7,761 cases from 288 test files, every one the glyphs HarfBuzz
expects**, through both font-functions, with `--verify`'s own checks in
HarfBuzz passing for each. **And 545 fonts loaded by FreeType**, their
first 48 glyphs rendered hinted at 24 pixels and unhinted at 13, the
bitmaps and metrics fingerprinted. 835 lines in all, a test file's or a
font's each, every one the line the same `texttest.c` says on this Mac
against the same releases built natively. 5.3 s in the guest.

Six of the 545 are not faces to FreeType, on the Mac as in the guest: the
fonts HarfBuzz keeps to prove it survives broken ones.

**Controls**: one byte in the middle of each font, turned over for the
reference only (`KOSMOS_TEXT_BREAK=fonts`), and 832 of the lines differ;
one case made to expect a glyph it will not get (`=expected`), and
HarfBuzz's expectations are not met, naming that case.

W5e is last because it is the largest and stands on W5a's pictures and
W5b's text.

## W5c - built: SQLite 0.11.389, libxml2 and libpsl 0.11.390

**SQLite 3.54.1**, as sqlite.org ships it: the amalgamation, one
`sqlite3.c`, which is the library, and the source tree for the programs
that test it. sqlite.org publishes no SHA-256; what its download page
gives is SHA3-256, so `upstream.py` holds the two zips to that
(`digest()`, `sum_of()`). SQLite has no CMake, and one file is its build:
the Makefile compiles it unmodified, `fuzzcheck`'s own options from
`main.mk` and Kosmos's three.

- **The lock is a directory** - `unix-dotfile` as the default VFS. The
  servers keep no locks on files, so `flock` and `fcntl`'s record locks
  are refused with ENOTSUP (`struct flock` and `F_SETLK` exist so a port
  compiles, and says so when it asks). A connection that writes makes
  `<database>.lock` with `mkdir`, which `diskfs` makes or refuses
  atomically. What it costs: a process that dies holding a write leaves
  the directory, and the next writer is busy until somebody removes it.
  Locks kept by the servers would answer that, and are not built.
- **Temporary files in `/Temporary`**, through `sqlite3_temp_directory`,
  SQLite's own door for it and the first it asks. Kosmos has no
  environment and none of `/var/tmp`, `/usr/tmp` and `/tmp`, so `VACUUM` of
  anything too large for memory had nowhere to put its copy.
- **`SQLITE_PRINTF_PRECISION_LIMIT` left out** of `main.mk`'s options: it
  cuts `speedtest1`'s longest `CREATE TABLE` short, on this Mac too.

The POSIX layer grew what SQLite's Unix layer names: `struct flock` and
its three commands, `fchown`, `sys/uio.h`'s `struct iovec`, and
`memory.h`. `sys/ioctl.h` is not one of them: `ioctl` is a name Kosmos
does not have even for ported code, so the header is an empty one, in
`runtime/posix/refused/` since W5d, where OpenSSL's `signal.h` joined it.

**Held to:** `tools/run_sql.py`, the gate's `x86-sql`, booting
`sqltest.elf` twice on one `/Home`. The programs are SQLite's own and the
Mac's are built by the runner from the same sources with the same options.

1. **`fuzzcheck` over the eight fuzz databases SQLite ships** - 46,391
   SQL scripts and database files, each run, checked for errors and
   leaks, with 9,839 query invariants checked as well; each database's
   count of tests held to this Mac's, and none failing. 80 s under TCG,
   4 s natively.
2. **`speedtest1 --verify`** on a database in `/Home`, every one of its
   test sets, and its verification hash - a hash of every row every query
   returned - held to this Mac's: `6218819e665a67f2a51a1747fa38315577939e524077c28a`.
3. **The lock**, `sqltest.c`: one connection holds an exclusive
   transaction, the lock directory is there, a second connection's write
   is busy, and once the first commits the second gets in and sees its
   rows.
4. **A reboot**: 5,000 rows written, fingerprinted and checked for
   integrity; the machine turned off; the same fingerprint read in the next
   boot, and this Mac's.

**Controls**: half of one fuzz database's tests taken out of the
reference (`KOSMOS_SQL_BREAK=fuzz`), and the counts differ, naming it; a
byte of the database turned over on the disk between the boots (`=keep`),
and the second boot's fingerprint is not the first's.

**What it found, which was most of the work**, and none of it SQLite's:

- **`printf` from ported code said nothing.** `SYS_WRITE` is the
  console's owner's alone, and a program at the prompt does not own it.
  The C library's `printf` already spills what is refused into a ring the
  Lua side drains (Doom's `doom.log()`); the POSIX layer's `stdout` and
  the C library's `puts` and `putchar` did not, and failed or dropped it.
  They spill now (`kosmos_spill`, `kosmos.h`), and `sqltest`'s door
  returns what the programs said.
- **A program's `exit` ended the process**, and with it what the program
  had said: `fuzzcheck` calls it after saying why it gave up. The two
  programs are compiled with `-Dexit=posix_program_exit`, which returns to the
  kit with the code, as their `main`s are renamed.
- **`realloc` used up the address space.** A block of a megabyte or more
  is an arena of its own, returned when freed, and `sys_map` never reuses
  an address. `fuzzcheck` grows a file in memory a page at a time, which
  was a new arena and the old one returned for every page, until the four
  gigabytes of the window were gone - "unable to realloc for 1269760
  bytes". A large block that has to move moves with half as much again
  now, so a block growing steadily moves a logarithmic number of times.
  The window itself is the question in `roadmap.md`.
- **256 KB of stack.** SQLite's query planner ran off a process's stack
  on the second fuzz database. On this Mac `fuzzcheck` fails at `ulimit -s
  512` and passes at 1024; the programs run on eight megabytes of their
  own, as Quake's engine does (`kosmos_call_on_stack`).
- **One library, two programs.** On the Mac they are two processes; here
  `fuzzcheck` gave SQLite a heap of its own (`memsys5`), freed it, and
  `speedtest1` allocated from it. Before each, the kit shuts SQLite down
  and puts every setting either changes back to SQLite's default.
- **Unlinked while open.** SQLite opens a temporary file and unlinks it at
  once, and POSIX keeps the file for its descriptors; a descriptor here is
  a path, so the next write would go to a name that had been deleted - it
  was fixed while the missing temporary directory was still being looked
  for, and `posixtest`'s control shows the write failing without it. An
  `unlink` of a path the process has open now marks it, and the last close
  removes it - `posixtest` holds that, with a control. Until then the name
  is still there for another process to see, which is where this differs
  from POSIX.

### libxml2 and libpsl

**libxml2 2.15.4**, GNOME's tarball held to the SHA-256 it publishes, built
by its own CMake with the rest (`tools/w5_build.py`): static, its programs
and tests off, threads on, and three things off because Kosmos has no
door for them - iconv, which the libc does not have and WebKit does not
need (it hands the parser text it decoded itself), ICU's converters, and
modules, which are `dlopen`. Its own tables convert UTF-8, UTF-16,
Latin-1 and ISO 8859-x. The Mac's reference is built with the same
options, so the two convert with the same code.

**libpsl 0.23.3**, the public suffix list a cookie's domain is held to,
for WebKit and for curl. It has no CMake, and two files are its build,
which the Makefile compiles as it does SQLite's: `psl.c` with the list
compiled in (the table its tarball ships, `ENABLE_BUILTIN`) and no IDN
library. WebKit and curl hand it hosts already in ASCII, and it carries
its own punycode for the list's own entries.

What they asked of Kosmos:

- **`glob` and `fnmatch`** (`runtime/posix/glob.c`). `runtest` finds its
  cases with `glob`, and libxml2's configure checks for it: without it,
  every list of cases is empty and `runtest` passes having tested nothing.
  Written whole - a wildcard in any part of the path, POSIX's flags,
  sorted - through `readdir`, so through the namespace. Held to this Mac's
  libc by `tools/test_glob.c` in the `host` suite: 7,497 answers, every
  pattern in a table against every name and flag, and folder trees globbed
  both ways. Two places POSIX leaves open or this Mac reads differently
  are decided and written down there: a backslash quoting nothing is no
  match, as on BSD and glibc; an unclosed `[` is an ordinary character, as
  POSIX and glibc say and this Mac's libc does not. The test found one bug
  before it shipped: `*` forgot `FNM_PERIOD` past a slash.
- **One way to run a ported program's `main`** (`posix_program.h`). The
  SQLite kit had it - a stack of the program's own, `exit` brought back to
  the kit, what it printed collected from the spill ring - and libxml2's
  and libpsl's tests needed the same three things. It moved into the POSIX
  layer (`posix_program_run`, `posix_program_exit`) and `kitenv`
  (`kit_push_spill`) rather than being copied, and `sqltest` stands on it
  now too.
- **`fscanf` never said the file had ended.** The POSIX layer's scanner
  read to the end and left the stream's end-of-file flag down, so a
  program that scans records until `fscanf` stops and then asks `feof`
  whether the file ended or failed to parse was told it failed: `runtest`
  said "invalid format" at the end of every one of libxml2's HTML
  tokenizer files, 13 errors. A scan that reaches the true end - for a
  descriptor, where `read` said so - raises the flag now, and `posixtest`
  holds it, with a control.
- **`setenv` and `unsetenv` refuse**, with ENOTSUP, as `flock` does.
  There is no environment (`getenv`), so there is nothing to put into
  one; `runtest` sets `XML_CATALOG_FILES` empty to have no catalogs, and
  has none here either way - nothing is set, and the default catalog's
  place has nothing in it.
- **A library's settings in `/Kosmos/Settings`.** CMake's default put the
  install folder on this Mac into libxml2 as its catalog's home - a path
  with a user's name in it, in the image. Every library built for Kosmos is
  told `/Kosmos/Settings` instead, the place `layout.md` plans for them.

**Held to:** `tools/run_xml.py`, the gate's `x86-xml`, one boot of
`xmltest.elf` on a `/Home` holding libxml2's `test/` and `result/` trees -
3,500 files, which is why the disk is sized by how many there are as well
as by their bytes (kfs gives one inode to every 64 KB) - and libpsl's list
and tests. The Mac's programs are built by the runner from the same
releases, libxml2 with the same options.

1. **libxml2's `runtest -v`**, started in the folder with the trees: all
   60 of its sections - parsing, push parsing, SAX, the reader, HTML and
   its HTML5 tokenizer, entities, DTD validation, XInclude, XPath and
   XPointer, Schemas, Relax-NG, patterns, C14N, catalogs on threads,
   regexps and automata - each one's count, errors and leaks held to this
   Mac's: **3,886 tests, no errors, no leaks**, in 23 s under TCG.
2. **libpsl's five tests**, each one's count held to this Mac's: 62, then
   324,270 over the whole list, 23, 68 and 93 - **324,516**, all passed.

**Controls**: a byte changed in one of libxml2's expected results on the
guest's disk (`KOSMOS_XML_BREAK=result`), and four tests fail; half of
libpsl's test list gone (`=psl`), and `registrable-domain` counts 54
against the Mac's 93. And `fscanf`'s fix taken out, and both `posixtest`
and `runtest` fail.

## W5d - built: OpenSSL 0.11.392, curl 0.11.393

**OpenSSL 4.1.0**, its release held to the SHA-256 GitHub publishes, built
by its own Perl `Configure` rather than CMake: `runtime/cxx/openssl-kosmos.conf`
is to it what `kosmos.cmake` is to the others - two targets,
`kosmos-x86_64` and `kosmos-aarch64`, the same compiler, headers and base
address (`tools/w5_build.py`). Static, its programs, documents and tests'
own build off, zlib on, settings in `/Kosmos/Settings/ssl`. **Its assembly
is kept**: AES-NI, SHA and the vector code on x86-64, NEON and the crypto
extensions on ARM, chosen at run time from what the processor says.

What it asked of Kosmos, and the answer each time:

- **`select`**, over `poll` in the POSIX layer (`sys/select.h`): a set
  becomes a list of descriptors, a closed one is EBADF, a hang-up wakes a
  reader and a writer alike. OpenSSL's BIOs wait with it.
- **`gethostbyname` and `getservbyname`**, over `getaddrinfo` and the
  layer's own table of services; `struct hostent`, `h_errno`, `EPROTO`.
  OpenSSL's fallback resolver is compiled even where it can never run, so
  the names have to exist.
- **`strtok`** in the libc and **`strtoimax`/`strtoumax`** in
  `inttypes.h`, for the test programs.
- **`getauxval` on ARM** (`sys/auxv.h`): what the processor can do, as
  Linux's HWCAP bits, computed from the ID registers Nebula already hands a
  process (`/Devices/cpu`). OpenSSL otherwise finds out by trying each
  instruction and catching the SIGILL, which needs signals.
  `OSSL_IMPLEMENT_GETAUXVAL` is the switch `armcap.c` sets for itself on
  glibc and the BSDs. `AT_SECURE` is 0: there is no set-uid.
- **No QUIC and no DTLS** (`no-quic no-dtls`): both want `socketpair`
  for a notifier between threads. Neither is something WebKit asks
  OpenSSL for; WebKit's HTTP/3 is its own.
- **`signal.h` refused**, as `sys/ioctl.h` is: an empty header in
  `runtime/posix/refused/`, found before the compiler's own, so a port
  that includes it compiles and one that calls `signal` does not.
- **No system log**: `-DNO_SYSLOG`, and the log BIO is OpenSSL's null one.

**Held to:** `tools/run_ssl.py`, in the gate as `x86-ssl-evp`,
`x86-ssl-slow` and `x86-ssl`, which run side by side. `ssltest.elf` holds
three of OpenSSL's own test programs, unmodified, each renamed and run in
a process of its own (the test library's counters are never reset). The
Mac's are built by the runner from the same release, and every run's
result lines are held to the Mac's, in order.

1. **`evp_test` over every vector file OpenSSL ships** - 116 files of
   ciphers, digests, MACs, KDFs, signatures and key exchange, in runs of
   90 (its argument limit is 100): **13,238 vectors** in 29 s, and the two
   SLH-DSA files that are most of the time on their own, 161 vectors in
   98 s.
2. **`bntest`**, the big numbers, over its own files and then its
   built-in cases.
3. **`sslapitest`** over OpenSSL's test certificates: TLS handshakes
   between two ends in memory, resumption, version and cipher
   negotiation, the callbacks and the record layer - with the big numbers,
   **6,875 results**, in 36 s.

**The processor the machines have.** The x86 suites run QEMU's `-cpu max`,
not its default `qemu64`, which has no AES-NI: OpenSSL used its plain C
for every cipher, the assembly the M700, the T14 and the Mac Pro run was
held to nothing, and the stitched AES-CBC-HMAC ciphers, which exist only
beside AES-NI, skipped all their tests. That one file still differs from
the Mac in which tests run and which skip, because x86 has stitched
ciphers ARM has not and the reverse; the runner holds their sum and none
failing.

**Controls**: one expected digest changed in `evpmd_sha.txt` on the
guest's disk (`KOSMOS_SSL_BREAK=vector`), and the first run fails;
a byte of `servercert.pem` changed (`=cert`), and 691 of `sslapitest`'s
results fail. The control was first aimed at the test root, which
`sslapitest` never opens, and then at the server's key, a byte of which
halfway down is in a part signing never reads - both passed, the second
on the Mac as well.

### curl - built, 0.11.393

**curl 8.23.0**, its release held to GitHub's SHA-256, by its own CMake
(`tools/w5_build.py`): the static library, and its program's objects -
compiled by curl's CMake with its own `curl_config.h` - archived with
`main` renamed and `exit` brought back to the kit, for the Makefile to link
into `curltest.elf`. On OpenSSL, the system's one TLS; W5a's zlib; libpsl,
compiled by the Makefile as for W5c. Off, and why:

- **HTTP/2**: nghttp2 is not built yet. WebKit's network stack asks curl
  for it; it is the next library on curl's side (roadmap).
- **The threaded resolver**: it signals its answer down a socketpair or a
  pipe, and the POSIX layer has neither, so a name is looked up as the call
  is made. That is a wait inside the call, which *Nothing waits on
  hardware* forbids on the desktop's paths; the roadmap has it.
- **IPv6**: the POSIX layer's sockets are IPv4 and TCP.
- **SSH, LDAP, Kerberos, IDN, brotli, zstd**: nothing here asks for them,
  or nothing here supplies them.
- **A default bundle of roots**: `/Kosmos/Settings` is not served yet
  (`layout.md`); the TLS Kit's step onto OpenSSL brings Mozilla's roots
  as a file, and then curl's default is that file.

**Its trials are linked, against a stand-in for the image.** `kosmos.cmake`
makes CMake's trials static libraries - there is nothing to link a program
against - so a trial is compiled and never linked, and
`check_function_exists` says yes to any name. curl turns its trials back
into programs, rightly: of the 29 functions it asks about that way, 18 are
not here (`pipe`, `eventfd`, `sendmsg`, `getpwuid`...). Its trials are
linked by `x86_64-elf-ld` or `aarch64-elf-ld` against one object holding a
weak symbol for every name the libc, the POSIX layer and the system's calls
define - read from their objects, which the Makefile builds first - so a
trial links exactly when what it calls exists. The list is kept with the
configuration, and a name added to the POSIX layer configures curl again.

What it asked of Kosmos:

- **`sys/time.h` brings `sys/select.h`**, as glibc's and this Mac's do and
  POSIX allows: curl's public header declares `curl_multi_fdset` with
  `fd_set` and includes only `sys/time.h` for it.
- **The refused headers on every CMake port's path** (`kosmos.cmake`):
  curl includes `signal.h` whatever it was told, and uses nothing from it
  it was told it does not have.
- **`posix_program_run_to`**: a ported program run with its `stdout` and
  `stderr` in a file - curl's says what it fetched there - which the
  OpenSSL kit had written for itself, and now shares.

**Held to:** `tools/run_curl.py`, the gate's `x86-curl`. curl's own
program in the guest fetches from HTTPS servers on this Mac, at 10.0.2.2,
with the test authority and certificates `run_tls.py` makes; the same
program built for this Mac from the same release fetches the same things
from servers of its own that serve the same bytes. Every command's exit
code, `--write-out` line and the SHA-256 of what it saved are held to this
Mac's, and this Mac's to what the suite says it did:

1. **A page**, 309 KB, over TLS; **the same gzip'd** (`--compressed`),
   **chunked** in pieces of every size up to 10 KB, and **behind a
   redirect** (`-L`, one hop).
2. **Cookies and the public suffix list**: a server at `www.kosmos.co.uk`
   sets one cookie for itself and one for all of `co.uk`; the jar keeps
   the first, refuses the second - libpsl's answer - and sends only the
   first back.
3. **Three refusals**, each curl's 60: the certificate for another name,
   out of its dates, and signed by an authority the guest was not given.
4. **8 MB**, its bytes, in 1.3 s under TCG.

**Controls**: a byte of the guest's page changed
(`KOSMOS_CURL_BREAK=page`) - the four commands that fetch it differ; the
guest's server sets its second cookie for its own domain (`=cookie`) - the
jar keeps it, and the echo says so.

## W5e - built, 0.11.395

**Skia as WebKitGTK 2.54.2 carries it** (`Source/ThirdParty/skia`,
milestone 154), built by WebKit's own CMake beside WTF and
JavaScriptCore - `USE_SKIA` on in `runtime/cxx/jsc.cmake`, its encoders
off until libwebp's mux is built - into `libSkia.a`. Ganesh, its GPU
renderer, is compiled with the interface that finds no native GL, so
what draws is the processor until there is a GL or Vulkan driver.

What it asked of Kosmos, as `0012-skia-on-kosmos.patch`:

- **Fonts from a folder.** WebKit's Skia asks for Fontconfig everywhere
  but Windows and the PlayStation. Kosmos's fonts are files, found by
  Skia's own manager for a directory (`SkFontMgr_custom_directory`) over
  the same FreeType W5b built - the Text Kit's engine, so no second copy.
- **Unix, by name.** An operating system Skia does not recognise falls
  through to `SK_BUILD_FOR_MAC`, and then wants `xlocale.h`, `malloc/malloc.h`
  and Grand Central Dispatch. Kosmos says `SK_BUILD_FOR_UNIX`, PUBLIC, and
  FreeType's version is the one it was built as: there is no `dlopen` to
  ask a newer one with.
- **No streams.** Kosmos's libc++ is built without localization, so there
  is no `<sstream>`. Five of Skia's files use one, to print a float or
  read one, or to split a string into lines; where
  `_LIBCPP_HAS_LOCALIZATION` is 0 they do it with `snprintf`'s `%g` and
  `strtod`, which is what a stream in the C locale does, and they are
  unchanged elsewhere.
- **Two sources its list leaves out**: `SkOSPath`, which the folder's
  font manager joins paths with, and `SkStrikeRef`, which `SkFont` calls.
  A link that throws unreached functions away, as WebKit's builds do,
  never sees either; Kosmos's images keep every function of an object
  they take, so the one call nothing makes still has to be answered.

And of the runtime: libm's `float` halves (`fmaf`, `fmaxf`, `fminf`,
`ilogbf`, `llroundf`, `lrintf`, `nextafterf`, `rintf`, `fmodf`, `exp2f`)
and `llround`, `remainder` and `remquo`, from musl 1.2.5 as the rest are;
`fenv.h`'s exception flags, which `fmaf` tests; `EOVERFLOW`; and in the
POSIX layer, counting semaphores (`semaphore.h`, on the same futex the
mutexes wait on), `malloc_usable_size`, `newlocale` and `uselocale`
for the C locale alone - and **a file mapped privately**:
`SkData::MakeFromFileName` maps the file and has no other way in, and the
POSIX layer refused every file. `mmap` of a file with `MAP_PRIVATE` now
reserves the pages, reads the file into them with `pread` and gives them
the access asked for. POSIX leaves it unspecified whether a private
mapping sees what is written to the file afterwards, so a copy taken at
the call is one; `MAP_SHARED` of a file is still `ENODEV`. `posixtest`
holds it: the bytes, zero past the end, a write reaching only the page, a
write-only descriptor refused (control: a mapping that reads nothing).

**Held to:** `tools/run_skia.py`, the gate's `x86-skia`. `skiatest.cpp`
draws eight scenes into RGBA surfaces of its own: fills (winding and
even-odd, quadratics, cubics, conics, a rounded rectangle, an aliased
square turned), strokes (every join and cap, dashes along a circle and a
curve, hairlines, a thin stroke under a scale), gradients (linear in all
four tile modes, radial, sweep, two-point conical, and one interpolated in
OKLab, premultiplied, as CSS asks), text (IBM Plex Sans in four sizes, bold,
italic aliased, Plex Mono hinted, and a glyph grown and turned), pictures
(libpng's and libjpeg-turbo's own test images decoded by Skia's codecs and
drawn shrunk and stretched with nearest, linear, mipmapped and cubic
sampling), effects (eight blend modes, a layer with an alpha, an
antialiased clip, a blurred mask, a blurred layer, a drop shadow, a sepia
colour matrix), a recorded picture played back twice, and a destination in
linear sRGB, so that every colour goes through skcms. Each scene is said as
a line - an FNV-1a of its pixels and how many it painted - with a line for
each picture decoded, each font family found and each string measured.

**The reference is the same file on this Mac, built for x86-64 and run
under Rosetta**: Skia by the same CMake with the same patch
(`tools/webkit_build.py host-x86_64`, through a small wrapper,
`runtime/cxx/skia-reference/`, since the whole of WebKit does not
configure on a Mac from the GTK release), and FreeType, libpng,
libjpeg-turbo and zlib by `tools/w5_build.py host-x86_64`. Both sides take
the same vector paths - SSE2 as the baseline, and the AVX2 and AVX-512
code Skia picks at run time - so the lines must be identical, and one
pixel drawn differently is a line that disagrees. And `skia_defines.h`,
what the test compiles with so that Skia's headers mean what the
library's did, is held to what Skia's target declares PUBLIC, written out
by the reference build from the target's own property.

**Twenty-three lines, every one as on this Mac**: five pictures, three
families, four measured strings and eight scenes, in 0.6 s under TCG.
Before that was true there were two differences, both the test's: the
folder's families came in the order the file system lists them, which is
not the Mac's, so they are said sorted; and no picture could be read,
which was the mapping above.

**Controls**: a byte inside the JPEG's picture data turned over for the
reference only (`KOSMOS_SKIA_BREAK=picture`) - its picture line and the
scene that draws it disagree; a define added to what the header is held to
(`=defines`) - that check fails.

Left for later, in the roadmap: Skia's encoders, which want libwebp's
`mux` library; libc++ with localization, which would let the five patched
files be as they ship; and Skia for AArch64, with its suite, when ARM's
tests resume.

## Where the time goes

Nothing in W5 is on a path a person waits on yet. W6 is where Skia's
rasterising, HarfBuzz's shaping and the picture decoders start to matter,
measured on real cores and never under TCG. What W5 measures is that each
library is correct here, and how long each takes to build.

## Disk

13 GB are free on this Mac after W4. `webkit.md` asks for space before W5,
because WebKit's whole build wants tens of gigabytes. But W5's libraries
are small: together, their sources unpacked are a few hundred megabytes,
and their objects for one processor about as much again. Skia is the
largest, at an estimated gigabyte or two of objects. **W5 fits. W6,
WebCore itself, does not**, and the question is there rather than here.

**Measured at the end of W5** (13 November): Skia's objects for x86-64
are 20 MB, not the gigabyte guessed - WebKit's flags build without debug
information - and the whole of `build/webkit/x86_64`, WTF, bmalloc,
JavaScriptCore and Skia, is 324 MB; W5's libraries for every target are
464 MB, and the patched source 514 MB. 9.9 GB are free on this Mac. WebCore
is many times JavaScriptCore's size, so W6 still asks the question.

## Decided by Diego, 12 November 2026

1. **Fetched, as W4 is**, not vendored. `tools/upstream.py` gets each
   release and holds it to its publisher's SHA-256. The tree keeps the
   sums, Kosmos's glue and patches.
2. **zlib itself**, 1.4 of 5 November 2026, which libpng, FreeType,
   libxml2, curl and OpenSSL are written and tested against. The Compress
   Kit moves from `miniz` onto it in a step of its own, so the system
   keeps one deflate.

What was asked, kept as it was asked:

1. **Fetched, or vendored?** `webkit.md` says each of W5's libraries is
   "vendored as shipped under `runtime/upstream/`". After it was written,
   the 11 November decision fetched WebKit and ICU instead, by size.
   W5's libraries are a few hundred megabytes of source together, OpenSSL
   and HarfBuzz the largest. A repository whose whole history is 256 MB
   would grow by about that.
   - **Fetched, as W4 is (recommended).** `tools/upstream.py` gets each
     release and holds it to its publisher's SHA-256. The tree keeps the
     sums, Kosmos's glue and patches.
   - **Vendored**, as `webkit.md` says, and as `expat`, `miniz` and
     `bearssl` are.
2. **zlib.** libpng, FreeType, libxml2, curl and OpenSSL all ask for
   zlib's interface. Kosmos has one deflate today: `miniz`, vendored in
   `runtime/upstream/miniz/` with zlib's names turned off, behind the
   Compress Kit (`inflate.c`, `deflate.c`, `gzip.c`), which `png.c` and
   the PDF reader ask.
   - **zlib itself (recommended)**, 1.4 of 5 November 2026, which every one
     of the five is written and tested against. The Compress Kit then
     moves from `miniz` onto it, in a step of its own as the picture
     decoders and TLS are moving, so there is still one deflate.
   - **`miniz` with zlib's names turned on**: nothing new, at the risk
     that it lacks calls those five make (`inflateReset2`, `gzopen` and
     others). Each gap would be a patch to a port, or code added to
     `miniz`'s side.
