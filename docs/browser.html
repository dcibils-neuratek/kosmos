What the window is made of

  • Tabs as the title bar. Each one a page with its own back and forward; the window is dragged by the strip after them, and the three circles close, minimise and zoom as on every window. A new tab opens on favorites and what was open lately.
  • The kit’s header: back, forward, reload (stop while loading), the address field, the sidebar, and the menu. The field says how the page came before anything else: Secure for a certificate that checked out, Not encrypted for plain HTTP, Refused when a certificate did not. Clicking it shows the certificate. The host is dark and the rest dim, so the part that matters is the part that is read.
  • Favorites: the star in the field adds or removes one; the bar under the header shows the first ones and folders of them; the sidebar has all of them. Each favorite a file in /Home/Favorites with its address as an attribute — NetPositive’s way, so Tracker files, renames and moves them, and a folder there is a folder on the bar.
  • History: the sidebar’s other half, by day, searched as typed; kept thirty days unless Settings says otherwise, in /Home/Preferences/browser.
  • Settings, a page of the browser’s own in Preferences’ cards: the home page, what opens at start, the favorites bar, text size, images, the page’s costs, how long history is kept, the authorities trusted and any added, where downloads go.
  • The status line is the page benchmark. Where a link under the pointer goes on the left; on the right, what the page cost - fetch, parse, layout, paint. Clicking it opens the breakdown, and the test page (assets/www/) is the page those numbers are measured on.

Resizable, like every browser

Today the browser is a window that draws its own pixels, and the window manager refuses to resize one: its surface is shared and has a size. That changes for every such window at once, the browser first:

  1. Dragging the grip draws an outline, as any window’s does; the page stays as it was until the pointer lets go.
  2. On letting go, the window manager tells the program its new size; the program makes a surface that size, lays the page out again in it, and hands it over; the window manager shows the new one from the next frame.
  3. Cafesa3D, Camera, Video and Doom get the same, since it is the window manager’s and the kit’s rather than the browser’s.

The toolbar, the field, the tabs and the sidebar are the kit’s own widgets, painted into the window’s surface by ui.paint_view as Cafesa3D’s are — so a window can draw its own page and still wear the new components.

What Diego decided, 30 September

“great! it looks amazing.” And:

  1. A bad certificate is refused, with an Open anyway — “yes but add a button that says ‘open anyways’ as well so i can browse it anyway”. For that tab only, the field saying Not secure while it is open, nothing remembered.
  2. Favorites as files in /Home/Favorites, NetPositive’s way — “yes”.
  3. Tabs.
  4. The page’s costs always in the status line — “yes”.
  5. Searching from the address field, DuckDuckGo by default and Google as the other, chosen in Settings — “duck duck go as default, or google as well. put the options in settings as default search engine”.

And fast: “the browser needs to be fast!! we might need to do it mostly in C wiuth just LUA as the orqhestrator?” — the parser, the styles, layout and painting are C already, `browser.lua` deciding what to fetch and draw; the test page and the profiler say what else moves.
