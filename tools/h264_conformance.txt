# The H.264 conformance streams `tools/test_h264.c` decodes, one a line:
# the name FFmpeg's own test suite gives it (its reference checksums are
# `runtime/upstream/ffmpeg/tests/ref/fate/h264-conformance-<name>`), the
# file under https://fate-suite.ffmpeg.org/h264-conformance/, its sha256,
# and what it exercises.
#
# They are the ITU-T/JVT conformance bitstreams (H.264.1), which FFmpeg
# serves for its FATE suite, and 11 MB between them - too much to carry in
# the tree, so `tools/fetch_h264_conformance.py` puts them in
# `build/downloads/h264-conformance/` and holds each to its sum. The sums
# are of the files as fetched on 24 September 2026; the server publishes no
# signature to check them against.
#
# Chosen to reach every part of the decoder a film from a camera, a phone or
# the web uses: CAVLC and CABAC, B slices, weighted prediction, cropping,
# field pictures and MBAFF, many reference frames, and High profile's 8x8
# transform. Not the 10-bit and 4:2:2 High profiles, which decode and then
# have nothing to convert them (`user/kits/ffmpeg/h264_core.c`).
#
